## 一、引言

### 1.1 目的

定义 STARX 星选商城的业务范围、角色、功能与非功能需求，作为研发、测试与交付的统一依据。

### 1.2 背景

零售演示与中小品牌试运营需要一套**可部署**的全渠道商城：消费者可购物，商家可持续运营，平台可治理账号与内容。

### 1.3 术语

| 术语 | 说明 |
|------|------|
| SKU | 最小可售卖规格单元（如颜色+容量） |
| 商家工作台 | 卖家角色使用的运营后台 |
| 平台管理端 | 平台管理员账号治理与全局运营 |
| 模拟支付 | 演示环境内的支付成功/失败模拟，不对接真实收单 |

## 二、用户角色

| 角色 | 描述 | 主要操作 |
|------|------|----------|
| 游客 | 未登录访客 | 浏览商品、查看公开评价 |
| 买家 | 注册消费者 | 收藏、加购、下单、支付、收货、评价 |
| 卖家 | 商家运营 | 商品/SKU、库存、发货、评价处理、日志 |
| 平台管理员 | 平台运营 | 账号启停、角色治理、全局策略 |

## 三、核心业务流程

```mermaid
flowchart LR
  A[浏览商品] --> B[选择规格加购]
  B --> C[确认地址下单]
  C --> D[模拟支付]
  D --> E[商家发货]
  E --> F[确认收货]
  F --> G[评价]
```

## 四、功能模块

| 模块 | 优先级 | 能力摘要 |
|------|--------|----------|
| 用户与鉴权 | P0 | 注册登录、资料、JWT、角色 |
| 商品与目录 | P0 | 分类、搜索列表、详情多图、SKU |
| 购物车 | P0 | 加购、改数量、库存校验 |
| 地址 | P0 | 收货地址管理 |
| 订单与支付 | P0 | 下单、模拟支付、取消、发货、收货 |
| 收藏与评价 | P0 | 收藏、星级评价、审核与汇总 |
| 运营分析 | P1 | 热销榜、库存预警、销售看板 |
| 多端客户端 | P0 | PC、H5、商家、平台；Android 为增强 |

## 五、功能要点（摘要）

### 5.1 商品详情

- 支持多规格（外观/存储等维度分行选择）
- 支持按颜色切换图库
- 展示价格、库存、加购与收藏

### 5.2 交易

- 下单锁定 SKU 与数量
- 模拟支付成功后进入待发货
- 支持超时取消策略（可配置）

### 5.3 管理

- 商家：商品上下架、SKU 库存、发货
- 平台：账号启停与角色
- 评价：公开/隐藏影响前台展示与评分汇总

## 六、非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 列表分页；常规页面可交互加载 |
| 安全 | 密码哈希、鉴权、越权防护、密钥外置 |
| 兼容 | 现代 Chromium 内核浏览器；H5 主流机型 |
| 可运维 | Docker 编排、健康检查、日志与操作审计 |
| 数据 | 演示商品与 SKU 足以支撑完整购物演示 |

## 七、界面范围

至少覆盖：门户入口、商品列表/详情、购物车、结算、订单、个人中心、商家看板与商品管理、平台登录与用户管理、H5 等价主路径。
